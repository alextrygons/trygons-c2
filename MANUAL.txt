1. WHAT THIS PROJECT IS
-------------------------------------------------------------------------------
An autopilot for a boat, running on the Infineon KIT_A2G_TC375_LITE board
(AURIX TC375). There are two variants:

  * SMALL BOAT (default): outboard engine. The software controls the steering
    motor (no angle sensor: the angle is estimated), the throttle servo and
    the gear servo (Forward / Neutral / Reverse). It uses compass, gyro and
    GPS. It can hold a heading, hold a speed, drive to a waypoint, navigate
    without GPS (dead reckoning), calibrate itself (TRAINING), and it can
    be taken over at any moment with a hard-wired joystick.
  * BIG BOAT: rudder with an angle sensor, heading hold only.

The board has not arrived yet. All of the logic is written and tested in a
PC simulation, with a simulated boat. The parts that talk to the real
hardware are empty "stubs" for now (see chapter 13).

A PC ground station shows the boat live (values, map, plot, alarms) and
can send commands. It connects over the board's USB cable, or to the
simulator.

2. WHAT IS IN WHICH FOLDER
-------------------------------------------------------------------------------
  app/            The autopilot itself. Pure C, no hardware code. The same
                  files run on the board and in the PC simulation.
     smallboat.c    small-boat controller: owns all outputs, runs the modes
     autopilot.c    steering core (heading hold, outboard angle estimate,
                    end-stop detection, joystick angle steering)
     modes.c        mode manager: the ONLY place that changes the mode,
                    allowed-transition table, log of every request
     gear.c         gear state machine (idle -> neutral -> gear)
     throttle.c     throttle rate limits and reverse limit
     nav.c          waypoint navigation (track line, cross-track error)
     dr.c           position estimate: GPS when trusted, otherwise dead
                    reckoning; GPS integrity check (spoofing / jumps / drag)
     training.c     TRAINING: measures the outboard (gap, speed, end stops)
     calib.c        saves / loads the TRAINING result with a checksum
     joystick.c     joystick: calibration, wire-break detection, arming
     proto.c        frame format of the PC link (with CRC)
     link.c         PC link: telemetry, commands, heartbeat, settings
  hal/hal.h       The list of hardware functions the app may use.
  hal/hal_tc375.c The real board versions of those functions (stubs now).
  Cpu0_Main.c     Board start-up and the 20 Hz loop. Small boat by default;
                  "#define BOAT_VARIANT_BIG" at the top selects the big boat.
  sim/            PC simulation: boat model, simulated hardware, all tests,
                  and the simulated boat for the ground station.
                  NOT part of the board build.
  groundstation/  PC ground station (Python). See groundstation/README.md.
  WIRING.md       Wiring of the joystick and the USB link.
  CLAUDE.md       The project rules (also read by Claude).
  MANUAL.txt      This file.
  Libraries/, Configurations/
                  Generated by AURIX Development Studio. NEVER edit them.

3. WHAT TO INSTALL
-------------------------------------------------------------------------------
Already installed on this PC: everything in this list.
On a new PC, install:

  a) MSYS2 (https://www.msys2.org), which provides gcc and Python for the
     simulation. After installing, open "MSYS2 UCRT64" from the Start menu
     and run:

       pacman -S mingw-w64-ucrt-x86_64-gcc
       pacman -S mingw-w64-ucrt-x86_64-python mingw-w64-ucrt-x86_64-tk
       pacman -S mingw-w64-ucrt-x86_64-python-pyserial

     Then add  C:\msys64\ucrt64\bin  to the Windows PATH (Start -> "Edit
     environment variables" -> Path -> New), so that "gcc" works in any
     terminal.

     (Instead of MSYS2 Python you can use python.org Python: tick "Add
     python.exe to PATH" during install, then run  pip install pyserial )

  b) AURIX Development Studio (ADS) from Infineon, for building and flashing
     the board. It includes the compiler and the debugger driver for the
     board's USB (miniWiggler).

  c) Git (https://git-scm.com) and VS Code, for editing and saving your
     work. The project is on GitHub:
       https://github.com/alextrygons/trygons-c2.git

  To check that it works, open a terminal (VS Code: Terminal -> New Terminal)
  and type:
       gcc --version
       C:\msys64\ucrt64\bin\python.exe --version
  Both should print a version number.

4. THE PC SIMULATION: BUILD, TEST, TRY IT OUT
-------------------------------------------------------------------------------
BUILD (after every code change):
    cd C:\trygons\TRYGONS_C2\sim
    build_sim.bat
  It prints "BUILD OK" and creates sim\autopilot_sim.exe.
  (You can also double-click build_sim.bat in Explorer.)

RUN ALL TESTS (do this before every commit):
    autopilot_sim.exe all
  Each test prints [PASS] or [FAIL] with numbers. At the end:
    TOTAL: 66 passed, 0 failed
  The run takes a few minutes. If anything says FAIL, don't commit:
  find out why first.

  The tests cover the safety behaviour of every feature, for example:
  compass / gyro / GPS failure, gear changes, end stops, GPS spoofing,
  dead reckoning, TRAINING failures, joystick takeover from every mode,
  joystick wire breaks, PC commands refused, PC link lost, corrupted
  frames.

OTHER SIMULATIONS:
    autopilot_sim.exe              big boat, 5 minutes, writes sim_output.csv
    autopilot_sim.exe 4            same, at sea state 4 (1..5)
    autopilot_sim.exe outboard     small-boat steering table, writes
                                   sim_outboard.csv
    autopilot_sim.exe train        TRAINING (calibration) tests
    autopilot_sim.exe server       simulated small boat for the ground
                                   station (see chapter 5)
  The .csv files can be opened in Excel to plot heading, rudder etc.

5. THE GROUND STATION (PC PROGRAM)
-------------------------------------------------------------------------------
START IT WITH THE SIMULATOR (no board needed). Use two terminals.

  Terminal 1, the simulated boat (leave it running):
      cd C:\trygons\TRYGONS_C2\sim
      autopilot_sim.exe server
    or 5x faster than real time:   autopilot_sim.exe server 5760 5

  Terminal 2, the ground station:
      cd C:\trygons\TRYGONS_C2\groundstation
      C:\msys64\ucrt64\bin\python.exe app.py tcp:127.0.0.1:5760

START IT WITH THE BOARD (once the USB link is written, see chapter 13):
  1. Plug in the board's USB cable.
  2. Open Windows Device Manager -> "Ports (COM & LPT)" and note the COM
     number, e.g. COM5.
  3. Run:
       C:\msys64\ucrt64\bin\python.exe app.py COM5
  Or start "app.py" with no argument, pick the port from the list and
  press Connect.

THE WINDOW:
  Top bar          connection, "link: OK", name of the log file
  Orange banner    JOYSTICK IN CONTROL: PC buttons are refused now
  Red banner       active alarms (flashing + beep). "ACK ALARM" clears
                   them, in STANDBY only. "NO DATA FROM THE BOAT" appears
                   if the link stops for 3 s.
  Left column      mode, heading, target, yaw rate, outboard angle,
                   throttle, gear, GPS, position, speed/course, position
                   source (GPS / dead reckoning), uncertainty, water
                   current (set/drift), motor current, waypoint, training
  Middle column    mode buttons (STANDBY is the big red one)
                   heading -10 / -1 / +1 / +10 (only in CRUISE)
                   cruise speed, sea state 1..5
                   waypoint: type lat/lon or CLICK THE MAP, then
                   "Send waypoint"
                   training: Start, Accept (with measured full angle, 0 =
                   unknown), Reject
  Joystick strip   live stick position, TAKE/AUTO buttons, status,
                   "Hand back", "Calibrate start / finish"
  Map tab          boat, track, waypoint, uncertainty circle (green = GPS,
                   red = dead reckoning), drift arrow. No internet needed.
  Plot tab         heading vs target, and the outboard angle, last 2 min
  Config tab       "Read all", select a setting, type a value, "Write
                   selected". STANDBY only, range-checked, and LOST AT
                   POWER-OFF (RAM only).
  Events tab       every command, answer (OK / reason), mode change, alarm
  Bottom bar       the answer to your last command, green = OK, red =
                   refused with the reason

  Every command gets an answer. If the boat refuses, it says why, e.g.
  "JOYSTICK IS IN CONTROL", "only in STANDBY", "conditions not met (GPS /
  waypoint / sensors)", "not allowed (mode table)".

A NAV MISSION FROM THE GROUND STATION:
  1. Wait for GPS: FIX (green).
  2. Click the map where you want to go (or type lat/lon), set the speed
     (kn), and press "Send waypoint".
  3. Press NAV. The boat drives to the waypoint, slows down near it, and
     on arrival goes to idle + neutral (STANDBY) with the alarm "ARRIVED".

LOGS AND REPLAY:
  Every frame is saved in groundstation\logs\log_DATE_TIME.jsonl
    python replay.py logs\log_....jsonl --sim
        re-sends your commands to the simulator at the same boat times,
        and compares the mode changes with the recording
    python replay.py logs\log_....jsonl --view
        plays the recording back. Then connect app.py to
        tcp:127.0.0.1:5761 to watch it.
  (Use C:\msys64\ucrt64\bin\python.exe for "python" if python.org Python is
  not installed.)

END-TO-END TEST (ground station + simulator together):
    C:\msys64\ucrt64\bin\python.exe test_e2e.py
  Should end with  "E2E: 5 passed, 0 failed".

6. THE BOARD (AURIX TC375 LITE KIT)
-------------------------------------------------------------------------------
  1. Open AURIX Development Studio and open the workspace containing
     TRYGONS_C2.
  2. Build: the hammer icon. The sim/ and groundstation/ folders are
     excluded from the board build.
  3. Flash and run: connect the board over USB and press Debug (the bug
     icon), then Resume (F8).

  Choose the boat variant at the top of Cpu0_Main.c:
     /* #define BOAT_VARIANT_BIG */   <- commented out = small boat (default)
     #define BOAT_VARIANT_BIG         <- big boat

  What the board does today: it runs the 20 Hz loop and the alarm LED
  (LED1, P00.5). Every sensor reads "not available", so the software
  sits safely in STANDBY with all outputs off. The real hardware
  functions still have to be written (chapter 13).

7. HOW THE BOAT BEHAVES: MODES, BUTTONS, JOYSTICK
-------------------------------------------------------------------------------
MODES (small boat):
  STANDBY    engine idle, neutral, steering off. Start-up mode and safe
             state.
  MANEUVER   you steer with the steer lever (full angle). Gear F/N/R and
             throttle from the levers, max 30 %. Compass not needed.
  CRUISE     holds a heading and a speed (GPS speed). Forward only. Less
             steering at high speed, and it slows down by itself in rough
             water. Heading -10/-1/+1/+10 buttons work here.
  NAV        drives along the line from the start to the waypoint
             (corrects for current), slows down near it, stops on arrival.
             If GPS is lost or suspect it continues on dead reckoning at
             reduced speed.
  TRAINING   measures the outboard (gap, motor speed, end stops) at a slow
             fixed throttle. At the end it stops and waits for you to
             ACCEPT or REJECT the result. Accepted results are saved.
  JOYSTICK   the hard-wired joystick is in control (see below).

  Allowed mode changes (all others are refused and logged):
     from \ to   STANDBY MANEUVER CRUISE NAV TRAINING JOYSTICK
     STANDBY        -       yes     yes   yes   yes      yes
     MANEUVER      yes       -      yes   yes   no       yes
     CRUISE        yes      yes      -    yes   no       yes
     NAV           yes      yes     yes    -    no       yes
     TRAINING      yes      no      no    no     -       yes
     JOYSTICK      yes*     yes*    yes*  yes*  no        -
     * leaving JOYSTICK: only with the stick centred + AUTO (see below)

  Extra conditions: CRUISE/NAV need a working compass and GPS, and NAV
  needs a waypoint.

BUTTONS (boat panel):
  STANDBY/AUTO   any mode -> STANDBY. In STANDBY it acknowledges alarms.
  -10 -1 +1 +10  change the target heading (CRUISE).

JOYSTICK (manual override):
  * THE JOYSTICK ALWAYS WINS over the autopilot and the PC.
  * Take control: push the stick past 15 % for 0.1 s, or press TAKE.
    This works from EVERY mode. A short chirp sounds.
  * Stick left/right = outboard angle (full range).
    Stick forward = ahead, back = astern, centre = idle + neutral.
    Max throttle 40 % ahead, 30 % astern. Gear changes always go through
    idle -> neutral -> gear, even if you slam the stick from full ahead
    to full astern.
  * Give control back: CENTRE the stick, then press AUTO -> STANDBY. If
    the stick is not centred, AUTO is refused (chirp). The PC "Hand back"
    button follows the same rule. The autopilot never takes over again by
    itself.
  * At power-up the stick must be centred before it works. If it isn't,
    the alarm "JOYSTICK NOT CENTRED" sounds until you let go.
  * Broken wire: alarm "JOYSTICK FAULT". If the joystick was in control:
    idle, neutral, steering off, STANDBY.
  * Calibration (STANDBY): "Calibrate start" -> move the stick slowly to
    all four ends -> let go -> "Calibrate finish". It is saved with a
    checksum. If the result is bad, it is refused and the old one is kept.


-------------------------------------------------------------------------------
8. ALARMS
-------------------------------------------------------------------------------
  COMPASS LOST            compass silent. In CRUISE/NAV/TRAINING the boat
                          does a safe stop (gyro steering until idle +
                          neutral). In MANEUVER/JOYSTICK: alarm only.
  GPS LOST                no GPS fixes for 3 s
  GPS SUSPECT             a fix failed the integrity check (spoof flag,
                          jump, impossible speed, wrong course, slow drag)
  DEAD RECKONING LIMIT    position uncertainty > 200 m or > 10 min without
                          GPS -> CRUISE, slow, on the current heading
  ARRIVAL UNCERTAIN       at the waypoint by dead reckoning, but not sure
                          enough to call it "arrived"
  ARRIVED                 waypoint reached
  GEAR FAULT              neutral switch did not confirm neutral: throttle
                          held at idle, no more gear commands
  TRAINING                training aborted or failed
  JOYSTICK FAULT          joystick wire break / out of range
  JOYSTICK NOT CENTRED    stick not centred at power-up
  JOYSTICK TOOK CONTROL   the joystick override started
  PC LINK LOST            nothing heard from the PC for 3 s. The mode does
                          NOT change. It clears when the PC comes back.

  Alarms stay on until acknowledged (STANDBY/AUTO button in STANDBY, or
  "ACK ALARM" in the ground station).


-------------------------------------------------------------------------------
9. SAFETY RULES BUILT INTO THE SOFTWARE
-------------------------------------------------------------------------------
  * Gear changes only at idle: throttle idle -> wait -> neutral -> wait ->
    new gear -> wait -> throttle.
  * Every fault, timeout or STANDBY: throttle idle + neutral FIRST, then
    steering off.
  * Compass lost while moving: gyro steering (yaw rate 0) until idle +
    neutral, then off. Gyro lost too: outboard to centre, then off.
  * Throttle changes are rate-limited (up 15 %/s, down 40 %/s), and reverse
    is limited to 30 %.
  * Steering angle limits, end-stop detection (motor current or limit
    switches, if fitted).
  * GPS is trusted again after an integrity alarm only after many
    consistent fixes, and then the position is blended in smoothly.
  * One mode manager owns every mode change, and every request is logged.
  * The joystick always wins. The PC can never take control from it.

10. WIRING
-------------------------------------------------------------------------------
  Full details in WIRING.md. Summary (3.3 V ONLY, NEVER 5 V):

     X pot middle wire   -> A0  (X301 pin 1, P40.9)
     Y pot middle wire   -> A1  (X301 pin 2, P40.8)
     pot top ends        -> 1 kOhm -> 3V3 (X302 pin 4)
     pot bottom ends     -> 1 kOhm -> GND (X302 pin 6)
     100 kOhm from A0 to GND and from A1 to GND (broken wire -> fault)
     TAKE button         -> D2 (P02.0), other side GND
     AUTO button         -> D3 (P02.1), other side GND

  Ground-station link: just the board's USB cable (virtual COM port,
  921600 baud). Don't use D0/D1 at the same time.

  Other hardware (compass, GPS, servos, steering motor driver) has no pin
  plan yet. See chapter 13.

11. SETTINGS AND DEFAULT VALUES
-------------------------------------------------------------------------------
  Defaults are set in sb_default_config() (app/smallboat.c), gear.c,
  throttle.c and joystick.c. Change them there and rebuild. The settings
  marked (PC) can also be changed live from the ground station's Config
  tab (STANDBY only, lost at power-off).

  Gear servo pulses        F 1900 us, N 1500 us, R 1100 us
  Gear waits               idle 1.0 s, neutral 1.0 s, engage 0.8 s
  Throttle                 max 100 % ahead, 30 % astern,
                           +15 %/s up, -40 %/s down
  MANEUVER max throttle    30 %                          (PC)
  CRUISE                   start speed 8 kn, max 25 kn   (PC: max)
  Rough water              slows 2 kn steps, never below 5 kn
  NAV                      arrival 25 m, slow from 150 m, approach 4 kn
                                                          (PC: all three)
  GPS timeout              3 s
  Dead reckoning           NAV speed x0.7, limit 200 m or 10 min, then
                           CRUISE at 4 kn                (PC: all)
  TRAINING                 throttle 20 %, 30 s spin-up    (PC: throttle)
  Joystick                 deadband 15 %, engage 0.1 s, max throttle 40 %
                                                          (PC: deadband,
                                                           throttle)
  PC link timeout          3 s                            (PC)
  Steering gains           kp / ki / kd, turn rate        (PC)

13. WHAT IS STILL MISSING
-------------------------------------------------------------------------------
A) THE REAL HARDWARE FUNCTIONS (hal/hal_tc375.c)
   These are written now: timer (hal_millis) and the alarm LED. Everything
   else is a stub that says "not available":
     [ ] compass                  (e.g. NMEA on a UART)
     [ ] gyro / IMU (+ roll)      (e.g. on SPI or I2C)
     [ ] GPS                      (NMEA parser on a UART, with the
                                   receiver's spoof/jam flag if available)
     [ ] steering motor driver    (PWM + direction)
     [ ] steering motor current   (ADC), optional
     [ ] steering limit switches  optional
     [ ] throttle servo PWM       (GTM)
     [ ] gear servo PWM           (GTM, 50 Hz)
     [ ] neutral switch           optional
     [ ] paddlewheel speed sensor optional
     [ ] control panel: buttons, steer/throttle levers, gear selector
     [ ] joystick ADC + TAKE/AUTO inputs (pins chosen, see WIRING.md)
     [ ] flash storage: TRAINING result + joystick calibration
     [ ] USB link to the PC (ASCLIN0, 921600 baud)
     [ ] rudder angle sensor (big boat only)
   Before most of these can be written, the parts must be chosen: which
   compass, GPS, IMU, motor driver and servos.

B) TO DECIDE / CHECK ON THE REAL BOAT
     [ ] Pin plan for compass, GPS, IMU, servos, motor driver, panel
         (only the joystick pins are fixed so far).
     [ ] Measure the outboard (TRAINING does this): gap, motor speed, max
         angle.
     [ ] Set the gear servo pulses (F/N/R) and the waits for your gearbox.
     [ ] Check the speed / steering limits and rough-water settings at sea.
     [ ] Tune the steering gains on the water (the sim boat is a model).
     [ ] Enable the watchdogs (they are switched off in Cpu0_Main.c, as
         generated by ADS). They are important on a real boat.
     [ ] A hardware emergency stop (kill cord) that doesn't depend on the
         software.
     [ ] Check that the board and the joystick resistors give the expected
         ADC values (about 341 / 2048 / 3754 counts).

C) KNOWN LIMITATIONS OF WHAT EXISTS
     * Settings changed from the PC are lost at power-off.
     * A new waypoint is refused while NAV is running (leave NAV first).
     * Only one waypoint at a time (no route of several waypoints).
     * After an aborted TRAINING, the outboard angle estimate can be off
       by a few degrees until the next centring.
     * The "PC link lost" alarm clears itself when the PC comes back.
     * The ground-station map has no sea chart: it is a plain grid
       (offline).
     * The ground station has only been tested with the simulator, not yet
       with the real board over USB.
     * The big-boat variant has heading hold only (no throttle/gear/NAV).

14. TROUBLESHOOTING
-------------------------------------------------------------------------------
  "gcc is not recognized"
      C:\msys64\ucrt64\bin is not in PATH (chapter 3). Close and reopen
      the terminal after changing PATH.
  "python" opens the Microsoft Store
      Use the full path C:\msys64\ucrt64\bin\python.exe
  build_sim.bat says BUILD FAILED
      Read the first error line: it names the file and line number.
  Ground station: "Cannot connect"
      Is "autopilot_sim.exe server" running in another terminal? Is the
      port right (tcp:127.0.0.1:5760, or the board's COM number)?
  "cannot listen on 127.0.0.1:5760 (already in use?)"
      Another simulator is still running. Close it, or use another port:
      autopilot_sim.exe server 5770, then connect to tcp:127.0.0.1:5770
  PC buttons are refused with "JOYSTICK IS IN CONTROL"
      That's on purpose. Centre the stick and press AUTO (or "Hand back").
  Alarm "PC LINK LOST" in the simulator
      Normal when the ground station was closed, or when the simulator runs
      much faster than real time.
