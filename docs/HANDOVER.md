## 1. What the system is
A boat autopilot and remote-control system ("Trygons C2") for two small outboard boats (RF49D, ER69D; files in boats/).
The boat can be CREWED (someone on board, onboard joystick) or UNCREWED (driven from a shore station over 4G / RF / Starlink).
Hardware target: Infineon KIT_A2G_TC375_LITE (AURIX TC375, TriCore), built with AURIX Development Studio (TASKING).
**No hardware exists yet**: everything is written so it also compiles and runs on a PC (gcc simulator). The owner is new to VS Code, git and AURIX: explain simply.

## 3. Modes and features (all implemented in firmware + sim)
- **Modes:** STANDBY, MANUAL (joystick), HDG LOCK (±1/±10), AUTO (waypoint program ≤ 50 wp, AUTO RETURN), REMOTE (shore joystick via gateway), MANEUVER (steering + gear only, gear on the shore stick Y), DP (dynamic positioning: SPOT / JOG / CRUISE / TRIP with bow tunnel thruster + stern motor), TRAINING (outboard calibration), BENCH (dock test, USB laptop only), FIRST_TEST (compile-time: steering only, throttle 0).
- **Profiles:** CREWED / UNCREWED autodetected at power-up from the onboard joystick. UNCREWED: confirmations come from the shore captain's joystick; UNCREWED HDG LOCK and shore-stick override inside AUTO / HDG LOCK exist (throttle only ever lowered; lever = ceiling).
- **Lost link:** HELM station silent for LINK TIME (3 s default, captain can set 3..60 s, never near shore) → idle + neutral → STANDBY; near shore (< 50 m) engine kill at once, open sea after 10 s grace. Engine kill is a latch (cleared by power-on reset or a remote restart from HELM).
- **Actuators over DroneCAN** (node IDs static: AURIX 10, servos 20/21/22, relay board 30): throttle, 360° steering position servo, gear; steering model + TRAINING; relay board on DroneCAN or RS485 Modbus (build option `RELAY_BUS`). Hardware flags (`HAL_CAN_FITTED`, `HAL_CAN_SERVOS`, `HAL_RELAY_FITTED`, `HAL_SUPPLY_FITTED`, `HAL_JOY_FITTED`, `HAL_PADDLE_FITTED`, `HAL_THRUSTERS_FITTED`) stay **0** until the owner wires/confirms each.
- **Relays** (app/relays.c is the only writer): table from the boat file, stored in NV slot 7, changes only in STANDBY + CONFIRM; pairs, momentary ≤ 5 s, power_up only ON. **Engine controls / ignition:** IGNITION, STARTER (hold-to-crank ≤ 5 s + hardware time-limit relay), SHUTOFF (always allowed), remote RESTART (HELM, idle + neutral confirmed, no code). **Generator mode** (the only automatic throttle rise, neutral switch required, ≤ 30 %).
- **Navigation help (gateway):** shallow water from offline charts (EMODnet/GEBCO/OpenSeaMap, "not for navigation"), geofence polygon, AIS receive-only collision avoidance (CPA/TCPA, slow → route astern → DRIVER DECISION), vision obstacle detection (speed cap only, stage 3 off by default). Gateway can only *slow/steer in AUTO*; the AURIX validates everything.
- **Roles:** captain (manual licence, holds HELM) and copilot (prepares everything, driving changes need the captain's ACCEPT, STANDBY always free). Single-operator mode exists. Y/N questions use one vertical YES/NO layout, answerable with the shore stick.
- **Ground station extras:** alarms in one place, MASTER lamps, boat dropdown, tracks (GPX), screen recording + SAVE/KEEP, copilot camera view, loudhailer + boat microphone (captain takes the horn), recorded voice callouts (Piper / Windows voice), splash/About/icons, BATTLE SHORT = pure marketing theatre (no function, never give it one).
- **UAV magazine** (gateway/uav/): 6 small camera quads stacked under a hatch, launched in series by the copilot's prepare + captain's YES; MAVLink allow-list only, **camera drones only – no payload/release/strike function anywhere**; boat side is only the hatch relay (no AURIX change); battery-only forced landing, never RTL; manual flying with the shore joystick (captain only in STANDBY).
- **Academy + tour:** guided tour with real screenshots and 149 recorded Greek clips (academy/tour_voice/el, step 13u; English uses synthetic voice); lessons, quizzes, 10 emergency scenarios, video lessons, exams, practical test, certificates, UAV lesson.
- **Logging:** black box on SD (60 s ring split over 4 chunks), PC tools groundstation/tlg.py, log2csv.py, logview.py.

## 4. Safety rules that must never be broken (full text: CLAUDE.md "Safety rules")
1. Joystick always wins over autopilot/PC; the STANDBY button and e-stop always win (hard-wired, never over CAN).
2. Every fault/timeout/STANDBY → throttle idle + neutral FIRST, then steering off (hold for the position servo). "Idle" = the *modelled* servo position, not the command.
3. Gear change only at idle (idle → neutral → gear → throttle).
4. Nothing raises the throttle by itself except generator mode; navigation, vision, slamming, DP only lower/hold. Slamming restore needs the captain's ACCEPT.
5. Throttle up gentle (15 %/s), down fast (50 %/s), emergencies at once. Only app/servo.c writes servos (clamped to power limit); only relays.c writes relays; only thruster.c writes thrusters; check.sh greps for it.
6. Power limit starts 30 % fwd / 5 % rev at every reset, raising needs PC request + typed code + joystick CONFIRM, never saved.
7. Neutral-start interlock; held stick must be able to take over (HDG LOCK/AUTO/REMOTE refused with an off-centre stick).
8. CPU1 monitor trips on throttle > limit, gear change under throttle, core-0 heartbeat > 200 ms; watchdogs on all cores; logging never blocks control.
9. The gateway PC is *not trusted by the AURIX* (R7): station ids come from the gateway, so every driving change keeps an on-board physical check. AURIX limits the gateway (navreq lease 3 s, "no data = shallow").
10. No recursion, no malloc, big locals on core 0 are static, shared data uses SHARED_BEGIN/END in core 0's DSPR.
11. Every feature has sim tests for its failure cases; tests run with both joystick sources.
