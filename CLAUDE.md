# Trygons C2 — boat autopilot
- Target: Infineon KIT_A2G_TC375_LITE (AURIX TC375, TriCore). Built with AURIX Development Studio (TASKING).
- No hardware yet: all logic must also compile and run on PC with gcc for simulation.

## Architecture
- app/  — autopilot logic, pure C99, NO hardware or iLLD includes. Uses only hal.h.
- hal/hal.h — hardware interface (heading, rudder angle, rudder motor, buttons, time).
- hal/hal_tc375.c — real implementation with iLLD. Pins / priorities ONLY in hal/hal_pins.h (= WIRING.md). Drivers hal/tc_*.c (board only): tc_uart (ASCLIN, FIFOs; gateway TX = HAL_GW_TX_RING), tc_spi (QSPI1 = BNO085 on CPU0, QSPI2 = SD on CPU2; one bus per core), tc_bno085 (SHTP), tc_gps (UBX + NMEA fallback), tc_adc (EVADC), tc_sd + tc_fat32 (pure C, PC-tested by tests/hal_pc/fat32_check.py), tc_nv (data flash DFLASH0 record log, pure C over a port, API nvlog_*; PC-tested by tests/hal_pc/nv_check.py; also in the sim build for test DF4). Every driver: no blocking waits in the control loop (state machines), time limits, "no data" detection. Supply voltage = a tc_adc channel on A2 / AN37 (app/battery.c filters it; HAL_SUPPLY_FITTED 0 until the divider is wired). Unfinished: analog joystick, paddlewheel.
- sim/  — PC simulation: boat model + hal_sim.c + main. Excluded from the ADS build.
  `autopilot_sim server` = simulated boat on TCP 5760 for the ground station.
- groundstation/ — PC ground station (Python + tkinter). Frame format in app/proto.h,
  telemetry/commands in app/link.c; groundstation/proto.py must match them.
- Cpu0_Main.c — core 0: starts the small-boat controller (smallboat.c) by default; `#define BOAT_VARIANT_BIG` selects the big-boat autopilot.
- Cpu1_Main.c — CPU1: the independent safety monitor (app/monitor.c), nothing else.
- Cpu2_Main.c — CPU2: the logger (SD card).
- bridge/ — Teensy 4.1 USB joystick bridge firmware (PlatformIO, C++). Excluded from the ADS build. Frame format app/jsframe.c/.h is shared (compiled into both).
- Joystick sources: app/joystick.c is the one joystick interface; analog (joy_step) or USB bridge (app/joybridge.c) fill the same joy_input_t. Source + button/axis map: app/joymap.c (NV slot 4, CRC, STANDBY only).
- app/servo.c — the ONLY code that writes the throttle servo (power-limit clamp). app/powerlim.c — power limit.
- Logging: app/logcore0.c (core 0 producer, fields in app/logfields.h) → app/logq.c (lock-free queues) → app/logger.c (core 2, SD card, black box). File format app/logrec.h; PC tools groundstation/tlg.py, log2csv.py, logview.py, tlgreplay.py.
- tools/mapreport.py — memory report (ADS map, GCC elf, or `--objects` = expected memory per core before a build); FAILS if CPU1 RAM > 60 %. tools/check.sh — the test gate (sim all + bridge, TriCore compile, HAL/servo checks, memory, gateway tests); run before every commit.
- Data shared between cores (g_mon, log queues, g_logstat, g_timing) is placed explicitly in core 0's DSPR with SHARED_BEGIN()/SHARED_END() (app/memplace.h) - never in the cached LMU; tools/mapreport.py checks it (objects: section .bss_cpu0; ADS map: no 0x9... address). New shared data must use it too.
- Black box (app/logger.c): 60 s = 1200 x 184 B, split in 4 chunks (DSPR2 + cpu0/1/2_dlmu LMU); NEVER in CPU1's DSPR1 (only the safety monitor lives there).
- PARTS.md — the one shopping list (boat, gateway, cameras, sensors, AIS, shore). Keep it updated with every hardware change.
- gateway/ — Raspberry Pi 5 gateway (Python, systemd services). The AURIX is NEVER on the network: it talks only to the Pi over a UART (ASCLIN1 P15.0/P15.1, 921600, same frames + CRC as the USB link, app/link.c port LINK_PORT_GW). The Pi keeps the full AURIX log copy (LOG_CHUNK, dropped first when the UART is busy, never control traffic), sets its clock from GPS (TIME), sends GW_STATUS at 1 Hz (silent 3 s → GATEWAY LOST alarm, no mode change). Sim: `autopilot_sim server` puts the gateway UART on port + 2; tests: gateway/test_gateway.py.
- AIS (section A, gateway/ais.py): RECEIVE ONLY (dAISy HAT / USB receiver, NMEA AIVDM); decoded on the Pi, NEVER on the AURIX. Targets stale 3 min (A) / 6 min (B), removed 15 min; AIS RECEIVER SILENT (GW_STATUS flag → alarm, advisory). Optional online feed (AISHub) only on sync-allowed channels, never STARLINK. Optional second GPS (AIVDO / GNSS of the AIS device) → GW_GPS2 → dr.c check gps2_check_m (off by default).
- Charts (section B): tools/chartprep.py (EMODnet DTM via ERDDAP CSV, GEBCO .asc gap fill, OpenSeaMap via Overpass) → charts/<area>/ (not in git); groundstation/chart.py reads them (depth = shallowest cell around a point, no data = shallow), mapview.py draws the layers. Always the note "Not for navigation - free data, may be inaccurate near the coast" + attribution. Works offline.
- Navigation request (GW_NAVREQ, section C/D): the gateway decides (shallow water, collision avoidance), the AURIX validates and applies ONLY in AUTO (speed cap = reduction only, avoidance heading) or as a one-shot HDG LOCK heading after the driver's ACCEPT; MANUAL / REMOTE: alarm only. Lease 3 s: lost in AUTO while steering / slowing → hold heading, the lower of nav_lost_kn (4) and the last cap, DRIVER DECISION alarm. Joystick / STANDBY win. The AURIX also limits the Pi (R6): a HEADING request needs a speed cap, an AUTO heading more than nav_max_dev (150°) off the leg track is not steered (cap still applies, DRIVER DECISION), a HDG_SET is applied only if it arrived while already in HDG LOCK. Shallow limit = max(3 m, draft + margin) (gateway shallow.py); AUTO programs / AUTO start through the gateway refused across or near shallow water (code 114); no data = shallow.
- Collision avoidance (section D, gateway/avoid.py + Gateway.nav_compose): CPA/TCPA per AIS target, warn 0.5 nm / 10 min, danger 0.25 nm / 6 min (COLLISION RISK + SAVE). AUTO: slow → re-check → route astern (starboard first, never ahead of a bow, safe_nm, depth-checked) → rejoin when the way back is safe; HDG LOCK: proposal + the captain's ACCEPT (avoid_answer, only the captain's screen 1 / single-op) incl. the return; MANUAL / REMOTE: alarm only. Unsolvable (≥ 2 dangers, turning target, stale data, no safe route) → DRIVER DECISION: min_kn, keep course, never an unchecked route. Every decision in the audit log (kind "avoid"). Tests: gateway/test_avoid.py (planner) + test_gateway.py section CA (end-to-end). AIS doesn't show small craft: the docs must keep saying so.
- Section E: simulated AIS traffic = gateway/simais.py (AisSim, traffic() mix of Class A / B, CLI for `autopilot_sim server`). Ground station: AIS tab (list joined with CPA / TCPA, details on click), collision line on the driver HUD, HDG LOCK proposal as ACCEPT / REJECT on the driver screen (app.drv_proposal → avoid_answer); tests test_driver.py I7, test_avoid.py E1.
- Demo (no hardware): START_DEMO.bat / STOP_DEMO.bat / DEMO_SHIP.bat -> demo/demo.py (sim `server 5760 1 usb origin=37.82,23.60`, gateway with demo_run/gateway.json, demo/demo_world.py = 4 test cameras + AIS, ground stations SHORE + ON BOARD). Output in demo_run/ (gitignored). External programs are found by gateway/toolpaths.py (MediaMTX in tools/bin/ via tools/get_mediamtx.py, ffmpeg) - never hard-code temp or PC-specific paths; tools/check.sh runs from any clone.
- Vision (Part 2, gateway/vision/): eWaSR (Apache-2.0) ewasr_resnet18 ONNX in its OWN process (worker.py: IDLE / nice 19, limited cores + threads, newest frame only), manager.py on the gateway (health ACTIVE / PAUSED / DEGRADED / OFFLINE = notices, never alarms or mode changes; persistence filter; stages). ## Rules
- Floats OK (TC375 has FPU). No malloc. Fixed control loop rate (e.g. 20 Hz).
- Safety first: rudder angle limits, rate limits, sensor-timeout -> standby + alarm.
- The joystick always wins over the autopilot and the PC. Only a centered joystick (+ AUTO / HDG LOCK button, or PC + CONFIRM) leaves MANUAL.
- A held stick must always be able to take over: HDG LOCK, AUTO start / resume, REMOTE and TRAINING are refused while the onboard stick is not centred (joy.off_centre, also while it is ignored after STANDBY; the USB lever doesn't count - its pickup keeps the throttle idle) → PC NACK 8 "centre the joystick", HDG LOCK button: refused + chirp.
- The STANDBY panel button always wins (every mode; the PC can never override it).
- Joystick, panel buttons and link wiring: see WIRING.md (section 6: USB bridge).
- Tests run with BOTH joystick sources: `autopilot_sim all` and `autopilot_sim all --bridge` must both pass.

## Small-boat features
Outboard boat (small-boat variant, `AP_STEER_OUTBOARD`). The big-boat variant (rudder feedback) must keep working unchanged.

Actuators
- Steering motor without angle feedback (angle estimated from motor run time, backlash compensated).
- Throttle servo (0–100 %).
- Controls: joystick (X steering, Y throttle, TAKE / AUTO / CONFIRM), panel buttons STANDBY, HDG LOCK, -1, +1, -10, +10.
- Or USB joystick (Thrustmaster T.16000M stick + TWCS throttle via the Teensy bridge): non-returning lever, neutral zone 45–55 %, maps to the CURRENT power limit (a raised limit never makes the throttle jump), throttle pickup on takeover, lever override (10 % from the hand-back position), button map with no shared TAKE/AUTO/CONFIRM.
- Gear servo F / N / R, positioned by PWM pulse width (configurable positions).

Sensors
- Compass (heading), gyro (yaw rate; roll rate if available).
- GPS via UART: lat, lon, SOG, COG, fix, timestamp, receiver spoof/jam flag.
- Optional: speed sensor (paddlewheel), neutral switch, steering motor current, steering limit switches.
- app/dr.c: position estimate — GPS when trusted, dead reckoning otherwise (learned current + throttle→speed table, uncertainty). Every fix passes an integrity check (spoof flag, jump, speed, course, slow drag); a rejected fix counts as GPS failure.
  - A fix with NaN / infinite / out-of-range numbers (dr_fix_valid: lat ±90, lon ±180, SOG 0..100 kn, COG 0..360) is a rejected fix too (DR_WHY_INVALID, recovers like after a suspect fix) and its numbers are never used (sb gps.last keeps the previous values). Second GPS frames out of range are ignored (gps2.bad); non-finite DR inputs (heading, yaw, water speed, throttle) are not used.

Modes — three driving modes + STANDBY + TRAINING
- STANDBY: idle, neutral, steering off. Power-up and after every fault.
- MANUAL (joystick): X = outboard angle, Y = throttle fwd/rev via the gear state machine. Entered from ANY mode by X deflection (> 100 ms), Y deflection (not in HDG LOCK) or TAKE. Left only with the stick centred.
- HDG LOCK: panel button locks the current heading, ±1/±10 adjust (buttons or PC); throttle stays on joystick Y; joystick X → MANUAL.
- AUTO: waypoint program (app/program.c, ≤ 50 waypoints, validated, stored with checksum) from the PC; start / resume = PC command + joystick CONFIRM within 10 s; pause / resume / skip from the PC; joystick → MANUAL, program suspended.
- TRAINING: outboard calibration, only from STANDBY by the PC.
- FIRST TEST (compile-time `#define FIRST_TEST` in Cpu0_Main.c -> cfg.first_test; never from the PC): steering only. Throttle demand 0 + gear N every step (servos at idle / neutral); arms without joystick / neutral switch (ignored) / gateway; only STANDBY, TRAINING, HDG LOCK (MANUAL / AUTO / REMOTE refused, joystick takeover not requested); HDG LOCK / TRAINING steer only while "moving ahead" (GPS trusted, SOG >= 2 kn, COG within 60 deg of the heading); takeover = STANDBY button + emergency stop; TELEM2 group I + ground-station banner. Tests FT1-FT5.
- BENCH TEST (MODE_BENCH, dock test; normal + FIRST TEST build): only from STANDBY, only the USB laptop (link.c: PROTO_T_BENCH from any other station -> NOT_ALLOWED), not moving (GPS trusted > bench_max_kn 1.5), not with the e-stop. Throttle 0 + gear N; steering only in pulses 100-300 ms (sb_bench, through the core's manual steering: estimate, max angle, end stops; one per 0.2 s; refused toward an open limit switch); panel buttons only recorded (STANDBY still wins); buzzer test; monitor trip test (g_mon.test_trip = MON_TEST_TRIP, code SB_BENCH_TRIP_CODE) = a real latched trip (MON_TRIP_TEST) for checking the safe outputs (R3). Ends by itself (WHY_BENCH_END): 10 min idle, USB link lost, HELM not USB, moving. BENCH_DIAG frame (0x8D, USB, 10 Hz) with hal_get_diag(). Ground station tab "Bench". Tests BT1-BT6.
- EMERGENCY STOP (every config): hal_read_estop (NC contact of the e-stop that cuts the actuator power) pressed -> STANDBY (WHY_ESTOP, forced) + alarm SB_ALM_ESTOP; no mode but STANDBY while pressed; the alarm stays while pressed.
- REMOTE MANUAL (MODE_REMOTE): the shore PC's joystick through the gateway (CREWED: someone on board; UNCREWED: section A/B below). Enabled only by the HELM station's request + joystick CONFIRM (on board; UNCREWED: the shore joystick); from STANDBY / HDG LOCK / AUTO, never from MANUAL. Priority: STANDBY button > onboard joystick > remote joystick > autopilot. Cap 20 % fwd / 5 % rev (never above the power limit), steering rate-limited, lever neutral zone + pickup. Data older than 300 ms / gap > 300 ms / latency > 400 ms → idle + neutral + gyro hold + alarm, STANDBY after 5 s, never resumes by itself. Ends on release, onboard joystick, STANDBY, any fault, HELM taken on board.
- HELM (section B): only the HELM station's commands are carried out (AURIX checks it, link.c); a station on the boat can always take HELM; remote HELM lost → REMOTE LINK LOST, HELM to nobody, no mode change.
  - Trust boundary (R7, by design): the station id and the "local" (on the boat) flag come from the Pi (GW_CMD envelope); the AURIX can't verify them. Everything that changes the driving therefore stays behind on-board physical checks (joystick wins, STANDBY, CONFIRM for AUTO / REMOTE / power raise, power limit, navreq limits) - never rely on "local" alone for a safety decision.
- Driver confirmation (fix F1; REPLACED by section D below: copilot actions need the captain's ACCEPT): captain actions that change the driving (proto.DRIVING_CMDS, never STANDBY) are held by the GATEWAY (stations.py) and only forwarded after the DRIVER screen's ACCEPT; no driver screen open → refused "driver screen not open"; REJECT / 10 s timeout / driver screen lost (1 s heartbeat) → refused. SINGLE-OPERATOR mode (captain screen, warning, banners on both screens, audited) → the captain's own confirmation instead; off when that station disconnects.
- CONFIRM (joystick) only answers a pending PC request, only with the stick centred and the joystick armed; it never changes the mode on its own. Entering STANDBY (button, fault, HELM lost ...) cancels any pending request (storm seed 389, sim MV4).
- One mode manager owns all transitions (explicit allowed-transition table, every transition logged). Nothing else changes the mode.

Safety rules — never break them
- Gear change only at idle: throttle idle → wait → neutral → wait → new gear → wait → throttle.
- Every fault / timeout / STANDBY → throttle idle + neutral FIRST, then steering off.
  - Until idle + neutral the boat is still steered: from MANUAL the onboard stick keeps steering (also a held, disarmed stick: joy.steer_x, STOP_STEER_STICK); from REMOTE the remote stick is ignored at once and the gyro holds; joystick fault → gyro hold (no gyro: centre). AUTO / HDG LOCK: heading hold (gyro if the compass is gone).
  - STANDBY has its own, faster throttle closing rate (throttle.rate_stop_pct_s, parameter stop_rate_pc_s, default 100 %/s = idle within 1 s); normal driving and a planned arrival stop (WHY_ARRIVED) keep rate_down (40 %/s).
  - Compass lost while moving (AUTO / TRAINING): keep steering on the gyro (target yaw rate 0) until throttle is idle and gear is neutral, then steering off. If the gyro fails too: drive the outboard to its estimated centre, then off.
  - Compass lost in HDG LOCK: gyro hold + alarm, throttle stays with the user; once idle + neutral: steering off, STANDBY.
  - Compass lost in MANUAL → alarm only, stay in MANUAL (manual steering doesn't need the compass).
  - cfg.fault_steer: GYRO (default) or CENTER (outboard to centre, then off); no setting turns the steering off at once (R14).
- GPS lost / suspect in AUTO: alarm, continue by dead reckoning at reduced speed; uncertainty > limit (200 m) or DR > 10 min → AUTO holds the current heading, slow, alarm. Never declare arrival while the uncertainty is larger than the arrival radius.
- After an integrity alarm, GPS is trusted again only after N consistent fixes that agree with dead reckoning; then blend smoothly (no steering jump).
  - Along the heading only (never across), DR's speed error may be allowed during that recovery - but ONLY with an independent check: the second GPS agrees (recover_along_frac 25 % of the distance run / water speed) or a paddlewheel (5 %). Then ~60 s after a spoof at speed; without either the old rule (can take minutes at speed: a slow along-course drag can't be told from a speed-table error). Test T3.
- Throttle changes are rate-limited.
- Nothing raises the throttle by itself. The ONE exception is GENERATOR mode (section K below: captain-enabled, gear N confirmed by the neutral switch, low bank voltage, small steps, capped by min(generator max, power limit), CPU1 knows the cap, stopped idle-first by any joystick / STANDBY / fault / gear request). Navigation, vision, slamming, DP and every other function may only lower or hold the throttle.
- Reverse power is limited.
- Power limit: every power-up / reset starts at 30 % forward / 5 % reverse; the raised limit is RAM only, NEVER saved.
  - Raising needs ALL of: PC request + the code typed by the user + joystick CONFIRM within 10 s. One step at a time (30 → 50 → 75 → 100; reverse up to 15 %).
  - Lowering is always instant (PC, TAKE / override, STANDBY button, any alarm / fault, PC link lost, GPS lost, TRAINING, long low speed); the throttle then comes down at its normal rate, never up.
  - Exceptions (they never lower the power limit; their reaction is defined explicitly): navigation advisories (SB_NAV_ADVISORY: AIS RECEIVER SILENT, COLLISION RISK, DRIVER DECISION, SHALLOW WATER, OBSTACLE AHEAD - in AUTO the navreq slows / steers, otherwise alarm only, so MANUAL / REMOTE throttle never changes) and the slamming RED alarm when "slamming RED action" = STEP (parameter slam_red_reset = 0, the default) does NOT lower the power limit (a sudden drop can be dangerous in a following sea); it reduces the throttle one step (app/slam.c), warns red and SAVEs. LIMIT_RESET (slam_red_reset = 1) = the normal alarm rule. Slamming never raises the throttle.
  - The clamp lives only in the servo output function (app/servo.c); no other code may write the throttle servo (the build check greps for it).
- Watchdogs are enabled on all cores; a frozen loop resets the chip.
- CPU1 runs an independent safety monitor (throttle vs limit, gear change at throttle, core-0 heartbeat > 200 ms) that forces idle + neutral + steering stop + alarm, latched in the HAL.
  - Big boat (BOAT_VARIANT_BIG): Cpu0_Main.c calls monitor_publish_steering_only() after every autopilot_step (heartbeat + running, throttle 0, limits 100 %): the monitor guards against a frozen core 0 there too (trip stops the rudder motor). tools/check.sh compiles that variant too.
  - The heartbeat is watched only once core 0's control loop wrote g_mon.running = MON_RUNNING (every step; CPU1 clears it at its start): a slow boot can't trip it; core 0 that never starts trips after MON_BOOT_MS (3 s, MON_TRIP_BOOT).
  - Board (hal_tc375.c): hal_safe_outputs sets the latch FIRST, then writes idle / neutral itself into the GTM TOM shadow registers (taken at the next 20 ms period end, never a cut pulse), steering motor pin low, relay open - so it works with core 0 frozen. Every core-0 output call re-checks the latch after its write (no race). Servo PWM: TOM0 ch 15 throttle (P02.7), ch 14 gear (P02.6), 50 Hz from CMU FXCLK2; low-level Gtm/Std driver (the Gtm/Tom/Pwm driver is not in the ADS build).
- Neutral-start interlock: outputs only arm at power-up with throttle idle, neutral confirmed and the joystick centred (USB: stick centred AND lever in the neutral zone). The joystick must be SEEN (not detected yet / USB bridge still starting = not armed, NOT ARMED alarm); only a boat configured without a joystick (cfg.joy_optional, analog source) arms without it.
- USB bridge: no valid frame 150 ms / > 5 CRC errors per s / stuck counter / device unplugged / invalid axis / learn mode = JOYSTICK FAULT (same as a wire break). Hand-back needs stick centred AND lever neutral.
- Alarm acknowledge (PC ALARM_ACK from any station, panel STANDBY in STANDBY) = sb_alarm_ack(): clears only alarms whose cause is gone; active conditions stay (link-lost bits are raised again every step while lost).
- CPU2 watchdog (500 ms): the logger calls hal_watchdog_kick_core() after every SD card call (wrappers sd_* in logger.c); HAL contract: each hal_sd_* call returns within HAL_SD_MAX_MS (200 ms) or fails (LOG FAILURE) - the board's SD driver (tc_sd.c: bounded state machine, time limits) keeps it.
- Logging must never block or slow control: core 0 / CPU1 only push into lock-free queues; full queue → drop + count.
- Every feature has sim tests for its failure cases.

## Crew, profiles, MANEUVER, screens, boats (design 2026-10-25 - source of truth)
Where an older line above says otherwise, this section wins. "TO CONFIRM" = a default / decision the owner still has to confirm; "TBD" = hardware not chosen yet.

A. Operating profile CREWED / UNCREWED (AURIX, sb_t.profile, autodetected - never set from the PC)
- CREWED when an onboard joystick (analog, or T.16000M + TWCS through the Teensy) is detected and passes its self-check (present, armed = seen centred, no fault; USB: bridge running, stick + throttle connected) within the detection window after power-up (profile_detect_ms, 6 s: longer than the USB bridge start-up). Otherwise UNCREWED.
- Latched at power-up. It may change ONLY in STANDBY, not stopping (idle + neutral reached), and only UNCREWED -> CREWED: a joystick plugged in on board and passing its self-check for profile_switch_ms (10 s TO CONFIRM). CREWED -> UNCREWED needs a power-up without the joystick (a CREWED joystick that fails or is unplugged is a joystick fault - the crew is still there). Every change is logged + alarm SB_ALM_PROFILE (an ordinary alarm: power limit back to the startup limits, pending CONFIRM cancelled), the outputs are disarmed until the neutral-start interlock of the new profile passes again (CREWED: joystick seen centred), shown on every screen.
- A joystick appearing or disappearing while not in STANDBY is a fault and does NOT switch the profile: CREWED = the existing joystick-fault handling (MANUAL / HDG LOCK / REMOTE / MANEUVER -> STANDBY: idle + neutral first, alarm); UNCREWED = alarm SB_ALM_PROFILE + STANDBY (idle + neutral first).
- Both profiles: the onboard STANDBY button and the e-stop are always active.
- Operating rule (MANUAL + checklists): UNPLUG the onboard joystick before any uncrewed operation; check the profile shown on the screens before leaving the dock.
- CREWED = the behaviour above, unchanged: onboard joystick > remote; every CONFIRM (AUTO start / resume, REMOTE, MANEUVER, power raise) on the onboard joystick. FIRST TEST is always CREWED (forced, whatever is plugged in; its behaviour does not change; no lost-link kill).
- UNCREWED: the onboard joystick is ignored completely (no MANUAL takeover, no CONFIRM, no joystick buttons, not needed to arm). The neutral-start interlock arms without it. Every CONFIRM comes from the shore captain's joystick = the HELM station's remote joystick CONFIRM button (GW_RJOY flags b2), with the same rules: stick centred (and lever neutral), within confirm_ms (10 s), only for a pending request. Power raise: code + one step at a time + 10 s window, lowering instant, startup limits after every reset, never saved. I. Data flash / NV (step 3)
- Board: hal/tc_nv.c on the TC375 DFLASH0 (iLLD Flash/Std un-excluded in .cproject; check_ads_ifx.py proves it; the command sequences are the IfxFlash.h inlines, issued by hal_tc375.c's port and polled through D0BUSY). Two regions A / B (8 logical sectors of 4 KB each = 32 KB, DFLASH0 sectors 0-15; erased pages read as 0) used as an append-only record log: a record = {magic "TRYN", slot | format << 8 | len << 16, seq | ~seq, payload padded to 8-byte pages, crc32 | ~crc32}; the trailer page is written first, the header page last (= the commit); a save appends the next record; the load takes the newest record of the slot with a valid CRC; when a region is full the live records are copied to the other region, then the full one is erased (wear levelling; a power loss during any write keeps the old record; both regions are scanned at boot, a cut swap is completed). Flash commands are a state machine (issue, poll busy each step, time limit 1 s -> NV FAULT), NEVER a blocking wait: nvlog_service issues at most a few page programs per step (NV_BUDGET_US 300) or one sector erase, and the flash is never read while a command runs; the control loop period and the CPU1 heartbeat are untouched. HAL API: hal_nv_save only queues (copied; 4 entries; a newer request for the same slot replaces the queued one), hal_nv_service(allowed) runs the writes only with allowed = true (smallboat.c: STANDBY and not stopping; Cpu0_Main.c big boat: AP_MODE_STANDBY) or before the control loop (boot counter: hal_nv_service(true) until !hal_nv_pending(), NV_BOOT_MS 2 s, watchdog kicked); hal_nv_load returns the newest record (a queued one first); hal_nv_pending / hal_nv_ok. Core 0 only (one flash master); never CPU1 / CPU2. tc_nv.c is pure C over a port (nvlog_port_t: read / erase_start / write_start / busy / failed / micros) = the same code on the PC.
- Slots: 1 joystick calibration, 2 AUTO program, 3 boot counter, 4 joystick source + map, 5 TRAINING result (calib.c saves / loads slot 5 through app/nv.c; hal_calib_save / load are gone), 6 generator learned value (section K), 7 relay table (owner clarifications). The app side (app/nv.c: nv_init / nv_load / nv_invalid / nv_save / nv_step / nv_status) keeps the version + CRC-32 of every record type as today (calib.c, joymap.c, program.c, joystick.c); an unknown version or bad CRC = defaults (never a half-read record) + nv_invalid(slot) = notice NV DATA RESET (TELEM2 group I config flags b1; b2 NV FAULT = the flash does not work, nothing is saved, loads keep working; b3 a save waits; log event 23 NV: what 1 record unusable / 2 fault, slot, resets; both screens show the notice, lang keys nv.reset / nv.fault).
